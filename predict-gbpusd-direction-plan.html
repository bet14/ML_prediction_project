Problem Definition

Target Variable Direction(t) = 1 if close(t+1) > close(t), else 0 — Binary classification on daily GBP/USD bid close price

The GBP/USD pair is one of the most liquid and traded currency pairs globally. Unlike EUR/USD, it carries additional volatility drivers: BoE monetary policy divergence from the Fed, UK political events (Brexit aftermath, trade agreements), and GBP's role as a risk-sentiment proxy. The methodology from Guyard & Deriaz (2024) on EUR/USD is directly transferable with key adaptations for UK-specific macroeconomic indicators.

GBP/USD — Specific Considerations

Why GBP/USD behaves differently GBP/USD (Cable) is the 3rd most traded pair globally. Its dynamics are driven by BoE vs Fed divergence, UK political risk (trade policy, fiscal events), and the strong historical negative correlation with USD strength (DXY). Post-Brexit, UK CPI and labour market data have gained outsized market sensitivity.
Literature Gap — Opportunity Most papers on GBP/USD direction use narrow 3-5 year windows with only historical price data. Integrating UK macro indicators (BoE rate, UK PMI, UK current account) as done by Guyard et al. for EA indicators, over a 10+ year horizon, is underexplored and constitutes a differentiator for this project.

Preprocessing & Feature Engineering

Target construction, data transformations, three dataset variants, and date encoding

Target Variable Construction

Binary Label Direction(t) = 1 if GBP/USD close(t+1) > close(t), else 0. Computed by shifting the close price series by -1. The final day has no target and is dropped from training. Class balance is typically close to 50/50 for daily Forex direction — verify and report.

Three Dataset Variants

Dataset 1 — Basic Daily

Only current day's OHLCV for all Forex pairs and indices, plus the most recent macro indicator values. No history window. Simplest feature space. Baseline.

Dataset 2 — 90-Day Lookback

Dataset 1 + the preceding 90 trading days of OHLCV for each Forex pair and index. Large feature space. Captures medium-term momentum and mean-reversion patterns.

Dataset 3 — Technical Indicators

Dataset 1 + derived technical indicators from time-series. Domain-knowledge feature engineering. In Guyard (2024) this dataset consistently achieved best accuracy.

Date Encoding

Tree-based models

Three ordinal integers: day-of-month, month, day-of-week. Trees handle ordinal splits naturally without inflating dimensionality.

Other models (SVM, LR, KNN)

Sine and cosine encoding for day-of-month, month, day-of-week. Preserves cyclical continuity (Dec → Jan wrap-around) without false ordinal relationships.

day_sin = sin(2π × day / max_day) day_cos = cos(2π × day / max_day)
Look-Ahead Bias Warning All features used at prediction time must be known at market close on day t. This means: macro indicator = last published value as of day t (not the value referencing period t); technical indicators computed on close(t); target = direction(t) requires close(t+1) and is only used as a label, never as a feature.

PCA Decorrelation

Each model is trained in two configurations: raw features and PCA-transformed features (full component retention — no dimensionality reduction, only decorrelation). Based on Guyard (2024), PCA consistently reduced accuracy on EUR/USD, suggesting temporal structure in the original feature space that PCA disrupts. Expected same behavior for GBP/USD — PCA experiments kept for completeness and scientific rigor.

Why PCA may hurt here PCA projects features into orthogonal components by global variance — it destroys the temporal ordering and the domain semantics of indicators like "days since BoE rate change". Decorrelation removes potentially informative collinearity that encodes real market relationships (e.g., GBP/USD and EUR/USD co-movement under USD strength).

Meta-Estimator Stacking

Stage 1: fit three base models on datasets 1, 2, and 3 respectively. Stage 2: train a second-level model on the concatenation of [stage-1 predictions, dataset 3 raw features]. Any of the 21 models can be used at either stage.

# Stage 1 — fit base models on each dataset representation
m1 = SVM().fit(X_ds1_train, y_train)
m2 = XGBoost().fit(X_ds2_train, y_train)
m3 = KNN().fit(X_ds3_train, y_train)

# Stage 2 — stack predictions as additional features
X_meta = np.column_stack([
    X_ds3_train,
    m1.predict_proba(X_ds1_train)[:,1],
    m2.predict_proba(X_ds2_train)[:,1],
    m3.predict_proba(X_ds3_train)[:,1]

meta_model = DecisionTree().fit(X_meta, y_train)

3-Stage Bayesian Hyperparameter Search

S1
Search 1 — Model Hyperparameters Only
Uses full feature set. Finds a good baseline hyperparameter configuration. Passes best point to Search 2.
↓
S2
Search 2 — Hyperparameters + Feature Category Selection
Selects which feature groups to include (e.g., include FTSE250? include UK PMI?). Warm-starts from S1. Passes best point to Search 3.
↓
S3
Search 3 — Hyperparameters + Fine-Grained Feature Selection
Selects individual features (e.g., include FTSE100 volume? include UK CPI days-since-update?). Warm-starts from S2. Largest search space, benefits from S1/S2 prior knowledge.

Cross-Validation Scheme — 8-Fold Rolling Window

Walk-Forward Validation (no data leakage) Training data: 2014–2020. Validation: 2021–2022 in rolling 3-month windows, each added to training set before the next window. Test set: held-out 2023 (never seen during training or validation). This mirrors live trading conditions where the model is retrained monthly.

Profit Formula

Cumulative Return Formula P(t) = P(t−1) × [close(t)/close(t−1)] if prediction=1 (long), or P(t) × [close(t−1)/close(t)] if prediction=0 (short). P(0) = 100. This simulates a CFD long/short strategy with no transaction costs (spread excluded for simplicity; can be added as sensitivity analysis). 
def compute_profit(y_pred, close_prices):
    P = [100.0]
    for i in range(1, len(y_pred)):
        if y_pred[i] == 1:   # predicted UP — go long
            P.append(P[-1] * close_prices[i] / close_prices[i-1])
        else:                 # predicted DOWN — go short
            P.append(P[-1] * close_prices[i-1] / close_prices[i])
    return P

annual_return = (P[-1] / P[0] - 1) * 100  # in %

Important: Accuracy vs. Profit Divergence

Guyard (2024) demonstrates that the model with highest accuracy is not necessarily the most profitable. A model catching large-move days correctly (even with lower win rate) outperforms one winning more small-move days. Always report both metrics — a 55% accurate model with 30%+ annual return is more valuable than a 58% model with 5% return.

GBP/USD Risk Factors

Higher Spread Cost GBP/USD typical spread is 1–2 pips vs 0.5–1 pip for EUR/USD. In live trading this erodes profit. The paper's profit formula ignores spread — a sensitivity analysis with spread deduction is recommended.
Event-Driven Volatility Spikes BoE rate decisions, UK CPI prints, and political events (budget announcements, trade policy) cause intraday moves that daily models cannot capture. Consider excluding the day of major announcements from evaluation, or adding a "high-volatility flag" feature.
Evaluation Protocol Two evaluation modes: (1) train on 2014–2022, evaluate on full 2023; (2) monthly rolling re-fit — add each completed month to training set and predict next month. Mode 2 is closer to real deployment and typically shows better stability.
