RESOLVED (mystery)
Why the earlier ONS attempts returned empty bodies — the v0 API this project originally targeted (api.ons.gov.uk/timeseries/.../dataset/.../data) is permanently retired (confirmed via developer.ons.gov.uk/retirement/v0api). It was never a network/firewall problem. The replacement v1 beta API (api.beta.ons.gov.uk/v1/data?uri=...) was live-fetched and confirmed working for both UK candidate series — see Section 5.

investing.com Composite PMI pages do not hold full history — both s-p-global-composite-pmi-1492 (USA) and composite-pmi-1934 (UK) economic-calendar pages were fetched live and returned only ~3-4 of the most recent releases, not 2014-2024 history. Corroborated by another user's own comment on the USA page complaining about exactly this depth cut. This is a data-availability limit on investing.com's side, not a scraping/anti-bot failure — see Section 5 for the full writeup and what it means for fetch_composite_pmi_wip.py.

USA_composite_pmi.csv / UK_composite_pmi.csv investing.com economic-calendar pages USA: investing.com/economic-calendar/s-p-global-composite-pmi-1492
UK: investing.com/economic-calendar/composite-pmi-1934		 SCRAPER WORKS, BUT SCOPE-LIMITED — a real scraper (fetch_recent_releases() in src/data/fetch_composite_pmi_wip.py) was built and tested live against both pages. Finding: these pages render only the last ~3-4 releases, not full 2014-2024 history — confirmed live for both countries, and corroborated by another user's own comment on the USA page complaining about exactly this depth cut ("is it possible to keep past months inputs up... or at least more than just two updates"). No CSV/historical export exists on this page type (unlike investing.com's per-instrument price-history pages). Trading Economics' chart (JS/XHR-rendered, no data in static HTML) and the danieleongari/investing_economic_indicators GitHub repo (just an indicator-name→URL-ID lookup table) were also checked — neither solves bulk historical access without a paid API key or JS execution. Net: the scraper is only useful as an incremental updater going forward, appending each new monthly release once it appears; it cannot backfill history. Full 2014-2024 backfill still needs the manual fallback documented in the script (transcribing S&P Global's own monthly press releases at pmi.spglobal.com, or a paid Market Intelligence subscription).
Practical conclusion: both UK ONS replacements are technically ready to run (pending a human compare-before-swap step for CPI). Composite PMI remains the one series with no free full-history path on either side of the Atlantic — the new scraper improves "staying current" but does not change that.
