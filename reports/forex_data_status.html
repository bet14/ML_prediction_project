3. Current findings / open decisions

DECISION
Dukascopy vs yfinance for forex volume — the spec recommends Dukascopy (genuine ECN tick volume) but that means downloading/decoding/aggregating roughly 800k-900k hourly .bi5 files for the full 13-pair, 2014-2024 backfill. yfinance's =X tickers are far lighter (same mechanism already used for equity) but FX volume on Yahoo is widely reported unreliable/zero. fetch_forex_wip.py implements both behind --source instead of silently picking one — see Section 4 for the full writeup. No final choice has been made; whoever runs the backfill should decide based on whether genuine volume is worth the cost.
VERIFIED LIVE
Dukascopy URL pattern returns a real binary body (not 404/HTML) — confirmed against EURUSD/2024/00/15/10h_ticks.bi5 during this session's research pass.
NOT LIVE-VERIFIED
The 20-byte tick record layout and the 0-indexed month convention in the URL are corroborated by multiple independent community sources (found via web search), not decoded against a real downloaded file in this sandbox (no outbound network). fetch_forex_wip.py includes a no-network round-trip self-test (--self-test) that proves the decode logic is internally consistent — it does not prove the layout matches Dukascopy's real bytes. Spot-check on a personal machine before trusting a full run.
SCALE
Full Dukascopy backfill (13 pairs × 11 years × ~24h/day, weekends/holidays mostly empty) is on the order of 800k-900k HTTP requests. --append merges on date, so an interrupted run can be safely re-invoked with the same date range rather than restarting from scratch.

4. Source research — Dukascopy vs yfinance (2026-06-19)

SourceEndpointProsCons
Dukascopy (spec's recommendation) https://datafeed.dukascopy.com/datafeed/{PAIR}/{YYYY}/{MM}/{DD}/{HH}h_ticks.bi5
LZMA-compressed, 20-byte tick records, free, no API key, no official pip package		 Genuine ECN tick volume (real ask/bid volume, not synthetic). URL pattern confirmed live this session. Tick-level only — daily OHLCV must be aggregated client-side from a very large number of hourly files. Byte layout corroborated by community sources, not decoded against a real file in this sandbox.
yfinance =X tickers e.g. GBPUSD=X, EURUSD=X, ... — same package already used for equity Lightweight, one call per pair per date range, same proven mechanism as fetch_equity_wip.py. FX "Volume" field on Yahoo is widely reported unreliable/zero for most pairs (no consolidated FX tape) — a real concern given the spec's OHLCV includes a volume column.
Practical conclusion: no source has been eliminated. fetch_forex_wip.py defers the choice to whoever runs the backfill, via --source.
